# VoyageAI — Project Documentation

## 1. Overview

VoyageAI is an AI-powered travel planning platform. Users describe a trip and get a full
day-by-day itinerary generated by an LLM, then manage that trip's hotels, restaurants, budget,
packing list, and travel documents from one dashboard.

**Tagline:** Plan Less. Travel More.

## 3. Architecture

```
Browser (React SPA)
   │
   ├── Supabase client (auth, database queries, storage, realtime, edge functions)
   │       │
   │       └── PostgreSQL (RLS-protected tables) + Storage buckets
   │
   ├── Groq API (direct client calls — itinerary generation, chat, vision OCR)
   │
   ├── Google Maps JS API (direct client calls — geocoding, places)
   │
   └── Supabase Edge Function → Resend API (server-side only, key never exposed to browser)
```

**Why the email path goes through an edge function and nothing else does:** Groq and Google Maps
keys are designed to be used from a browser with domain restrictions; Resend's API key is not, and
sending it to the client would let anyone extract it from network traffic and send email as your
domain. The edge function is the one deliberate "backend" in an otherwise client-heavy architecture.

## 4. Database Schema (ERD summary)

Run the four SQL files in `supabase/` in order. Summary of tables:

- **profiles** (1:1 with `auth.users`, auto-created on signup via trigger)
- **trips** (belongs to a profile)
  - **trip_days** (belongs to a trip)
    - **activities** (belongs to a trip_day)
  - **hotels**, **restaurants**, **expenses**, **documents** (each belongs to a trip)
  - **packing_list_items** (belongs to a trip)
- **destinations** (belongs to a profile — independent wishlist, not tied to a trip)
- **favorites** (belongs to a profile — generic, references a hotel/restaurant/destination by label)
- **notifications** (belongs to a profile, optionally references a trip)
- **ai_history** (belongs to a profile, optionally references a trip)

Every table has Row Level Security enabled with a policy scoping rows to `auth.uid()`, either
directly (`user_id = auth.uid()`) or transitively through a join to `trips` for child tables like
`hotels`/`activities`. No table is publicly readable.

Two database triggers exist:
1. `handle_new_user` — creates a `profiles` row when someone signs up.
2. `notify_trip_created` — inserts a `notifications` row when a trip is created.

## 6. What's Deliberately Out of Scope

Documented honestly rather than silently omitted:

- **Trip sharing between users** — the `favorites`/`notifications` schema supports the pattern, but
  there's no invite/share UI yet.
- **Scheduled emails** (monthly summary) — the template and send function exist; nothing calls it
  on a timer. This needs a Supabase scheduled Edge Function (cron), which requires a paid Supabase
  tier in some plans.
- **Automated tests** — no unit/integration test suite. If your rubric requires tests, this is the
  highest-value next addition.
- **Formal accessibility audit** — semantic HTML and `aria-label`s are used throughout, but no
  Lighthouse/axe run has been done to confirm specific scores.

## 7. Setup & Submission Checklist

1. **Database:** run all 4 SQL files in `supabase/` in numeric order, in the Supabase SQL editor.
2. **Storage:** confirm all 6 buckets exist (the SQL scripts create them).
3. **Env vars:** copy `.env.example` → `.env`, fill in Supabase, Groq, and Google Maps keys.
4. **Install & run locally:** `npm install && npm run dev` — verify signup → create trip → generate
   itinerary → add expense → check analytics, before you consider it submission-ready.
5. **Push to GitHub:**
   ```
   git init
   git add .
   git commit -m "VoyageAI initial submission"
   git branch -M main
   git remote add origin <your-repo-url>
   git push -u origin main
   ```
6. **Deploy to Vercel:** import the GitHub repo in Vercel, add the same env vars from `.env` in
   the Vercel project settings (Environment Variables), deploy. `vercel.json` is already configured
   for a Vite SPA (client-side routing rewrite included).
7. **Email (optional but recommended if your rubric checks Resend):** deploy the edge function
   (`supabase functions deploy send-email`) and set the `RESEND_API_KEY` secret before your demo,
   or the "Resend Integration" requirement will look unimplemented even though the code is there.
8. **Before your demo/viva:** create at least one real trip with a generated itinerary, a couple of
   expenses, a hotel and restaurant, and one uploaded document, so the app isn't empty when you
   present it.
